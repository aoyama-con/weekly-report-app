# 新人OJT週報自動生成システム - 概要説明

**最終更新日**: 2026-01-03
**バージョン**: 1.0

---

## システム概要

新人社員のOJT週報作成を自動化し、評価の標準化と管理側の読みやすさ向上を実現するB2B向け業務WEBアプリケーションです。

### 解決する課題

- 📝 **週報作成の時間圧迫**: 新人が週報作成に多くの時間を費やし、本来の業務時間を圧迫
- 📊 **評価基準のブレ**: 委託現場ごとに指導方針や報告書の規範が異なり、評価基準が不統一
- 🔍 **週報の品質バラツキ**: 個人差によるバラツキで管理側の状況把握に時間がかかる

### 期待される効果

| 指標 | 目標 |
|------|------|
| 週報作成時間削減 | **1/3以下** |
| ユーザー満足度 | **4.0以上/5.0** |
| 生成結果採用率 | **70%以上** |
| マスキング漏れ | **0件** |

## ユーザーロール

| ロール | 主な機能 |
|--------|----------|
| **新入社員** | 週報作成、AI生成、編集、提出、アドバイス閲覧 |
| **OJT実施者** | 週報レビュー、評価入力、アドバイス閲覧 |
| **管理者** | 全週報閲覧、検索、PDF出力、ユーザー・現場管理 |

## 主要機能フロー

### 週報作成フロー（新入社員）

```
[新入社員]
   ↓ 箇条書き入力
[週報作成画面]
   ↓ 「生成」ボタン → トーン選択
[LLM API] (社内向け/客先向け)
   ↓ 報告書文体に変換 (10〜20秒)
[生成結果表示]
   ↓ 編集（任意）
[提出]
   ↓
[DB保存] (status: submitted)
```

### レビュー・アドバイスフロー（OJT実施者）

```
[OJT実施者]
   ↓ 週報閲覧
[レビュー入力画面]
   ↓ ルーブリック評価 (6項目×5段階) + コメント
[保存]
   ↓ 自動でアドバイス生成開始
[LLM API] (新人向け/OJT向け)
   ↓
[週報詳細に表示]
   ↓
[新入社員/OJT] アドバイス閲覧
```

## 技術スタック

### フロントエンド
- **フレームワーク**: React 18 + TypeScript
- **ビルドツール**: Vite
- **UIライブラリ**: Material-UI または shadcn/ui
- **状態管理**: React Query + Context API
- **フォーム**: React Hook Form
- **バリデーション**: Zod

### バックエンド
- **ランタイム**: Node.js 20+
- **フレームワーク**: Express + TypeScript
- **ORM**: Prisma または TypeORM
- **認証**: JWT + bcrypt
- **API仕様**: RESTful API（OpenAPI 3.0仕様）

### データベース
- **RDBMS**: PostgreSQL 15+
- **マイグレーション**: Prisma Migrate
- **バックアップ**: 日次自動バックアップ（7日保持）

### AI/LLM
- **モデル**: OSS LLM (Llama 3.1 70B または Qwen 2.5 72B)
- **推論環境**:
  - ローカル: Ollama または vLLM
  - クラウド: AWS SageMaker / Azure ML / GCP Vertex AI
  - API互換サーバー: LiteLLM、OpenAI互換エンドポイント
- **プロンプト管理**: YAMLファイル + バージョン管理
- **モデル選択理由**:
  - コスト削減（API従量課金なし）
  - データプライバシー（社内運用可能）
  - カスタマイズ性（ファインチューニング可能）

### PDF生成
- **ライブラリ**: Puppeteer
- **フォント**: Noto Sans JP（日本語対応）

### インフラ
- **クラウド**: AWS
  - Compute: EC2 (t3.medium) - アプリケーションサーバー
  - LLM推論:
    - 選択肢1: EC2 GPU インスタンス (g5.xlarge以上) + vLLM
    - 選択肢2: AWS SageMaker エンドポイント
    - 選択肢3: ローカルサーバー + Ollama (小規模環境)
  - Database: RDS PostgreSQL
  - Storage: S3 (PDFアーカイブ、モデルキャッシュ)
  - Load Balancer: ALB
- **CI/CD**: GitHub Actions
- **監視**: CloudWatch + Prometheus (LLM推論メトリクス)

## FAQ

### Q1: LLM生成に時間がかかる場合はどうなりますか？
**A**: 10〜20秒を目標としていますが、推論サーバーの負荷状況により最大30秒程度かかる場合があります。タイムアウト時は再試行ボタンで再実行できます。vLLMなどの高速推論エンジンを使用することで、レスポンス時間を短縮できます。

### Q2: 客先向けのマスキングは完璧ですか？
**A**: 正規表現とLLMの二段階チェックを行いますが、100%の保証はできません。生成後に必ず目視確認し、必要に応じて手動編集してください。マスキング検出ログも記録されます。

### Q3: 過去の週報を修正できますか？
**A**: MVP段階では、提出後（submitted）の週報は編集できません。下書き（draft）の段階でのみ編集可能です。

### Q4: 評価基準（ルーブリック）は変更できますか？
**A**: MVP段階では固定です。Phase 2で管理画面からのカスタマイズに対応予定です。

### Q5: オフラインでも使えますか？
**A**: LLM推論サーバーを社内ネットワークに配置している場合は、インターネット接続なしで利用可能です。Ollamaなどをローカルサーバーで運用すれば、完全なオフライン環境でも動作します。

### Q6: PDFはどこに保存されますか？
**A**: ダウンロード形式で提供されます。将来的にS3への自動アーカイブも検討しています。
