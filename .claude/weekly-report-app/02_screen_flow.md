# 画面遷移図（MVP）

## 全体フロー概要

```
[ログイン画面]
    ↓ 認証成功
[ダッシュボード] ←───────────────┐
    ↓                           │
    ├→ [週報作成画面]            │
    │      ↓ 生成・提出          │
    │  [週報詳細画面] ←──────┐   │
    │      ↓                 │   │
    │  [PDF出力]             │   │
    │                        │   │
    ├→ [レビュー入力画面(OJT)] │   │
    │      ↓ 保存            │   │
    │  └──────────────────┘   │
    │                            │
    └→ [管理画面]                │
           ↓ 各種設定完了         │
       └──────────────────────┘
```

## 画面別詳細仕様

### 1. ログイン画面
**URL**: `/login`
**表示要素**:
- タイトル「新人週報管理システム」
- メールアドレス入力（type=email, required）
- パスワード入力（type=password, required, min=8）
- [ログイン]ボタン
- エラーメッセージ表示エリア

**遷移先**:
- 認証成功 → `/dashboard`
- 認証失敗 → エラー表示（同画面）

---

### 2. ダッシュボード（新入社員）
**URL**: `/dashboard`
**表示要素**:
- ヘッダー: ユーザー名、ロール表示、[ログアウト]ボタン
- [新規作成]ボタン
- 週報一覧テーブル
  - カラム: 対象週、現場、ステータス、提出日、[詳細]リンク
  - フィルタ: ステータス（draft/submitted/reviewed）
  - ソート: 対象週降順（最新が上）

**遷移先**:
- [新規作成] → `/reports/new`
- [詳細] → `/reports/:id`
- [ログアウト] → `/login`

---

### 3. ダッシュボード（OJT実施者）
**URL**: `/dashboard`
**表示要素**:
- ヘッダー（共通）
- 担当新人の週報一覧
  - カラム: 新人名、対象週、現場、ステータス、提出日、[レビュー]リンク
  - フィルタ: 新人名、期間、ステータス
  - バッジ: レビュー待ち件数

**遷移先**:
- [レビュー] → `/reports/:id/review`
- [詳細] → `/reports/:id`

---

### 4. ダッシュボード（管理者）
**URL**: `/dashboard`
**表示要素**:
- ヘッダー（共通）
- 全週報一覧
  - カラム: 新人名、対象週、現場、ステータス、提出日、OJT名、[詳細]
  - フィルタ: 期間（from-to）、社員（検索）、現場、ステータス
  - ソート: 対象週、提出日
- サイドメニュー
  - [ユーザー管理]
  - [現場管理]

**遷移先**:
- [詳細] → `/reports/:id`
- [ユーザー管理] → `/admin/users`
- [現場管理] → `/admin/sites`

---

### 5. 週報作成画面
**URL**: `/reports/new`（新規）/ `/reports/:id/edit`（編集）
**表示要素**:
- 戻るボタン → ダッシュボード
- フォーム
  - 対象週（日付ピッカー、デフォルト今週月曜）
  - 現場（ドロップダウン、必須）
  - 今週やったこと（textarea、placeholder: 箇条書きで入力）
  - 学んだこと/気づき（textarea）
  - 困ったこと/課題（textarea）
  - 来週やること（textarea）
  - 相談したいこと（textarea）
- [生成]ボタン
  - クリックでモーダル表示
    - トーン選択: ●社内向け / ○客先向け
    - [生成実行]ボタン
- 生成結果表示エリア（初回は非表示）
  - 各セクション見出し付き
  - 編集可能（textarea）
  - 検出されたマスキング用語のリスト（客先向けの場合）
- [下書き保存]ボタン
- [提出]ボタン（生成後のみ有効化）

**遷移先**:
- [下書き保存] → ダッシュボード（ステータス: draft）
- [提出] → 確認ダイアログ → ダッシュボード（ステータス: submitted）

**バリデーション**:
- 対象週、現場、「今週やったこと」は必須
- 提出時: 生成済みかチェック

---

### 6. 週報詳細画面
**URL**: `/reports/:id`
**表示要素**:
- 戻るボタン → ダッシュボード
- 週報メタ情報
  - 新人名、対象週、現場、ステータス、提出日
- タブ切替
  - [社内向け] / [客先向け]
- 週報本文（読み取り専用 or 編集モード切替）
  - セクション見出し付き
  - draft時は編集可能
- 評価セクション（reviewedの場合のみ表示）
  - ルーブリック6項目×点数
  - 各コメント
  - 総評
- アドバイスセクション（reviewedの場合のみ表示）
  - 新人向けアドバイス（ToDoリスト形式）
  - OJT向けアドバイス（指導ポイント）
- アクションボタン
  - [再生成]（draft時のみ、新人のみ）
  - [編集]（draft時のみ、新人のみ）
  - [PDF出力]（トーン選択ドロップダウン付き）
  - [レビュー入力]（OJTのみ、submitted時）

**遷移先**:
- [編集] → `/reports/:id/edit`
- [レビュー入力] → `/reports/:id/review`
- [PDF出力] → PDF生成（別タブ or ダウンロード）

---

### 7. レビュー入力画面
**URL**: `/reports/:id/review`
**表示要素**:
- 戻るボタン → 週報詳細
- 週報本文（上部固定、折りたたみ可）
- 評価入力フォーム
  - ルーブリック6項目
    - 項目名（説明tooltip付き）
    - 点数スライダー（1〜5）
    - コメント（textarea、任意）
  - 総評コメント（textarea、任意）
- [保存してアドバイス生成]ボタン

**遷移先**:
- [保存] → 処理中ダイアログ → 週報詳細（ステータス: reviewed）

**バリデーション**:
- 6項目すべて点数入力必須

---

### 8. ユーザー管理画面
**URL**: `/admin/users`
**表示要素**:
- [新規招待]ボタン → モーダル表示
  - メールアドレス（input）
  - ロール（select: 新人/OJT/管理者）
  - [招待メール送信]ボタン
- ユーザー一覧テーブル
  - カラム: 名前、メール、ロール、有効/無効、登録日
  - 各行アクション: [ロール変更]、[無効化]/[有効化]

**遷移先**:
- [ロール変更] → モーダル（select → 保存 → 同画面リロード）
- [無効化] → 確認ダイアログ → 同画面リロード

---

### 9. 現場管理画面
**URL**: `/admin/sites`
**表示要素**:
- [新規作成]ボタン → 作成フォーム表示
- 現場一覧テーブル
  - カラム: 現場名、登録日、[編集]
- 作成/編集フォーム
  - 現場名（input、必須）
  - プロフィールテキスト（textarea、例: 求める姿勢、注意点）
  - マスキング用語リスト（textarea、1行1用語、例: 案件A→プロジェクト）
  - [保存]ボタン

**遷移先**:
- [編集] → 同画面（フォーム展開）
- [保存] → 同画面リロード

---

## 状態遷移図（週報ステータス）

```
     draft
       │
       │ 新人が「提出」
       ↓
   submitted
       │
       │ OJTが「レビュー保存」
       ↓
    reviewed
       │
       │（Phase2: PDF出力後locked）
       ↓
    (locked)
```

## 権限マトリクス

| 画面/機能 | 新入社員 | OJT | 管理者 |
|-----------|----------|-----|--------|
| ダッシュボード（自分の週報） | ✓ | ✓（担当のみ） | ✓（全て） |
| 週報作成 | ✓ | × | × |
| 週報編集（draft） | ✓（自分のみ） | × | × |
| 週報閲覧 | ✓（自分のみ） | ✓（担当のみ） | ✓（全て） |
| レビュー入力 | × | ✓（担当のみ） | × |
| PDF出力 | ✓（自分のみ） | ✓（担当のみ） | ✓（全て） |
| ユーザー管理 | × | × | ✓ |
| 現場管理 | × | × | ✓ |

---

## モバイル対応方針（MVP）

- レスポンシブデザイン（スマホでも閲覧可能）
- 週報作成・レビュー入力はPC推奨（複数行入力が多いため）
- 閲覧・PDF出力はスマホでも可

---

## アクセシビリティ

- キーボード操作対応（Tab移動、Enter送信）
- スクリーンリーダー対応（適切なaria-label）
- 色覚異常対応（ステータスはアイコン+色）
